# 明日方舟集换式卡牌 Web 原型

本项目按模块验收推进。模块 1 至 7、8.1 与 8.2 已完成；当前实现模块 8.3：公网运行保护与故障恢复。

## 模块 1 验收范围

- Vite、React、TypeScript 工程可以构建。
- Excel 卡表可生成与界面解耦的运行时 JSON。
- 数据加载时校验卡牌、效果引用、阵营、同名卡上限和40张主卡组。
- 两套首测预组均可展示摘要。
- 可以切换预组、按类型筛选并查看每张卡的数量、属性和完整能力文本。
- 类型检查、数据测试和生产构建全部通过。

## 模块 2 验收范围

- 为双方主卡组创建独立实体并使用可复现随机种子洗牌。
- 完成起手五张、秘密调度与本地热座交接。
- 实现准备、抽牌、主要、结束阶段及先后手首回合差异。
- 实现DP增长、恢复、基础区域计数与抽空牌库判负。
- 自动保存并从浏览器本地快照恢复测试对局。

模块 2 不包含部署、撤退、攻击或卡牌效果执行。

## 模块 3 验收范围

- 每名玩家拥有七个等价干员部署位与基础部署容量 7。
- 主要阶段可从手牌选择干员、支付完整 DP 并部署至指定空位。
- 已部署干员记录当前生命、竖置状态和部署回合；刚部署干员不能主动撤退。
- 后续自己的主要阶段可主动撤退竖置干员，按照卡面数值返还 DP。
- 主动撤退的干员进入公开的再部署候场区，CD 设置为 1。
- 自己的准备阶段恢复干员，并处理候场 CD；CD 降至 0 的干员返回手牌。
- 对局快照升级为 v2，保存部署区和再部署候场状态。

模块 3 不包含攻击、击溃、战术支援、场地或卡牌能力结算；被击溃后使用卡面再部署 CD 将在战斗模块接入。

## 模块 4 验收范围

- 自己的主要阶段可选择竖置且非本回合部署的干员发起攻击；宣告后攻击者横置。
- 地面干员可攻击理智盾或任意横置敌方干员；高台干员可攻击任意敌方干员，但不能攻击理智盾。
- 选定目标后切换至守方公开信息界面，由守方选择合法拦截者或放弃拦截。
- 攻击理智盾时，竖置地面干员可拦截，带有卡面【拦截】的竖置高台干员也可拦截。
- 攻击干员时，只有目标以外且带有卡面【拦截】的竖置干员可拦截；拦截者随后横置并成为攻击目标。
- 攻击力严格大于防御力时使目标失去 1 点生命，否则不造成伤害；基础战斗不反击。
- 生命归零的干员按卡面 CD 进入再部署候场区；未被拦截的理智盾攻击移除 1 枚理智盾。
- 理智盾归零立即结束对局；对局快照升级为 v3，可保存未决攻击与攻防交接状态。

模块 4 只识别卡面直接印刷的【拦截】关键词。天赋、技能、战术支援、场地及其赋予或修改的能力留待模块 5 的通用效果执行器处理。

## 模块 5.1 验收范围

- 使用经过运行时校验的结构化效果指令，不从卡面自然语言直接修改对局状态。
- 支持按卡面顺序批量执行抽牌、恢复 DP、提高 DP 上限、失去与回复生命、ATK/DEF 修正和失去理智盾。
- 单项效果当前无法执行时记录为跳过，并继续结算后续效果。
- 多张抽牌逐张执行；中途无法抽牌或失去最后一个理智盾时立即结束对局，并停止剩余效果。
- 生命回复不超过卡面上限，生命归零的干员按卡面 CD 进入再部署候场区。
- 属性修正保存在部署状态中，界面显示当前 ATK/DEF，战斗使用修正后的数值。
- 执行器不会修改传入状态；结果和公开事件日志可确定性复现。
- 对局快照升级为 v4，保存干员的 ATK/DEF 修正。

模块 5.1 尚不负责能力发动、触发时机、目标选择、费用支付和持续效果自动失效；这些分别在模块 5.2 至 5.4 接入。

## 模块 5.2 验收范围

- 部署、主动撤退、战斗击溃和效果击溃会生成经过运行时校验的事件快照。
- 触发能力使用显式注册表匹配事件，不从卡面自然语言猜测执行指令。
- 已覆盖首测预组中时机明确的自身部署、自身撤退、自身击溃、另一名友方撤退/击溃，以及煌击溃拦截者的触发。
- 记录双方本回合已主动撤退与已被击溃的干员，带前置条件的部署能力只在条件成立时入队。
- 同一事件产生的能力进入同一批次；当前回合玩家控制的能力排在非当前回合玩家之前，同组使用稳定顺序保证复现。
- 触发项保存来源干员与事件主体快照，来源离开部署区后不会令能力消失。
- 队列非空时暂停其他对局指令，并显示批次、能力文本、控制者、优先组以及可选/必须结算标记。
- 对局快照升级为 v5，保存触发队列、序号与本回合事件事实。

模块 5.2 不替玩家选择目标，也不擅自决定带“可以”的能力是否发动。队列的逐项选择、跳过与效果提交将在模块 5.3 接入；持续效果到期与每回合限次将在模块 5.4 接入。

## 模块 5.3 验收范围

- 只允许结算队首能力；必发能力不能跳过，带“可以”的能力可由控制者选择发动或不发动。
- 每次结算时根据当前对局状态重新生成并校验合法目标，不沿用触发时的旧目标。
- 触发控制者变化时先进入本地热座交接页，接手前不显示该玩家的手牌选择。
- 支持部署区干员、横置敌方干员和再部署候场区卡牌等目标类型。
- 支持伤害、击溃、失去理智盾、候场CD减少/回手，以及“抽1弃1”的分步结算。
- 结算中产生的新触发在当前能力完成后入队，并排在原有同时触发批次之后。
- 已接入芬、杜宾、煌、克洛丝、凯尔希及整合运动首测干员的已注册触发效果。
- 芬与杜宾的“下一次部署”效果可以被合格干员消耗；获得的【拦截】和部署回合攻击权限会参与规则判断。
- 克洛丝的临时DEF修正会在本回合结束时撤销；未使用的“下一次部署”效果会在回合结束时清除。
- 对局快照升级为 v6，保存结算步骤、延迟部署效果及临时属性修正。

模块 5.3 已完成首测触发能力的玩家交互与即时结果。模块 5.4 将统一持续效果、关键词赋予、每回合限次与到期时点，替代当前为首测能力提供的最小状态承载。

## 模块 5.4 验收范围

- 使用统一的持续效果记录承载“下一次部署”、关键字赋予、部署回合攻击许可与临时属性修正。
- 每项效果明确记录来源、控制者、作用对象、消费条件与到期时点，并可随对局快照复现。
- 芬的下一次合格部署会将标记转换为附着的【拦截】效果；该效果在其控制者下个准备阶段开始时到期。
- 杜宾的下一次罗德岛部署会获得部署回合攻击许可；未消费的标记与已授予的许可均在本回合结束时到期。
- 克洛丝的临时 DEF 修正通过统一属性查询参与战斗，并在本回合结束时移除，不再直接改写永久属性。
- 干员撤退或被击溃时，所有附着在该实例上的持续效果一并清除。
- 能力使用次数按控制者、能力 ID 与回合记录；杜宾的能力严格执行“每回合限一次”。
- 鼠标悬停或键盘聚焦双方部署区、双方再部署候场区及当前玩家手牌时，会以预组浏览卡面样式显示卡牌基础数值与完整能力文本；生命、横竖状态和候场 CD 等实时信息仍由台面直接展示。
- 对局快照升级为 v7，保存持续效果、下一个效果序号与限次计数。

模块 5.4 完成模块 5 的通用能力基础设施。下一步将进入模块 6，对两套预组剩余的战术支援、场地、主动技能和完整卡牌效果逐张接入并记录玩法问题。

## 模块 6 拆分

- 6.1：战术支援基础链路。完成主要阶段使用、DP 支付、目标选择、进入废弃区与持续效果衔接。
- 6.2：完整战术支援。接入抽弃、检索与牌库底排序、条件使用、候场回手减费、额外费用和废弃区回收。
- 6.3：干员技能与指挥官指令。接入横置、DP 与击溃费用，以及技能目标和战斗期修正。
- 6.4：共享场地与整套回归。接入场地替换、在场触发、限次，并逐张验收两套预组。

## 模块 6.1 验收范围

- 「集中火力」与「集中突击」可在己方主要阶段从手牌使用。
- 使用时选择一名己方已部署干员、支付 1 DP，并将战术支援卡置入废弃区。
- 目标干员的 ATK 本回合提高 2；当前属性、攻击结算和持续效果面板读取同一份修正。
- 修正在本回合结束时自动移除；目标提前离场时随目标移除。
- 非己方主要阶段、DP 不足、卡牌不在手牌或没有合法目标时不能使用。
- 尚未接入的战术支援卡在手牌中明确标记为后续子模块开放。
- 规则内核与界面操作均有自动化测试覆盖。

## 模块 6.2 验收范围

- 两套预组的 10 张战术支援卡均可在主要阶段按合法条件使用、支付 DP 并进入废弃区。
- 「人员调度」与「队伍集结」查看牌库顶至多 4 张，选择符合费用与阵营条件的干员，并允许排列其余牌库底顺序。
- 「作战简报」完成抽 2 张后弃置 1 张的分步结算；待弃牌期间暂停其他对局操作。
- 「行动复盘」检查本回合主动撤退事实，抽 2 张，并执行每名玩家每回合同名卡限一次。
- 「重返战线」与「后续梯队」从 CD 为 1 的候场干员中选择合法目标，将其返回手牌，并使该卡本回合下一次部署费用减少 1。
- 「战地搜集」选择并击溃一名己方竖置整合运动干员作为附加费用，然后抽 2 张；此次击溃正常记录回合事实并产生触发能力。
- 「回收补给」检查本回合击溃事实，并从废弃区回收一张非同名的整合运动战术支援卡。
- 「集中火力」与「集中突击」继续通过统一持续效果令目标 ATK 本回合提高 2。
- 牌库抽空会立即结束对局；不合法目标、DP 不足、条件不满足和错误结算步骤均不会修改状态。
- 对局快照升级为 v8，保存战术支援的检索、排序或弃牌等待状态。

## 模块 6.3 验收范围

- 台面为敌我双方增加独立指挥官区，展示指挥官卡名、当前理智值、横置/竖置状态及专属指令；卡牌详情仍可通过悬停或键盘聚焦查看。
- 指挥官专属指令只可在己方主要阶段发动，统一校验横置、1 DP、每回合一次、合法目标与附加击溃费用；指挥官在其控制者准备阶段恢复竖置。
- 阿米娅指挥官可令一名合格的己方横置罗德岛干员主动撤退，且该撤退正常产生触发能力。
- 塔露拉指挥官可击溃一名己方竖置整合运动干员，使另一名己方整合运动干员本回合 ATK +2，并在其攻击击破干员时额外造成1格生命伤害。
- 已接入芙蓉、安赛尔、阿米娅、凯尔希、整合运动术师与梅菲斯特的主动技能，包括治疗、候场减 CD、直接伤害、免费部署和击溃附加费用。
- 主动技能要求来源干员竖置且不是本回合部署；发动后横置来源，并按卡面支付 DP 或击溃费用。
- 浮士德攻击横置敌方干员时，本次攻击 ATK +2；该修正进入实际战斗比较并写入事件记录。
- 所有主动能力先生成合法目标，再由玩家在台面完成选择；目标失效、费用不足或结算条件不满足时不会修改状态。
- 对局快照升级为 v9，保存双方指挥官的横竖状态。

## 模块 6.4 验收范围

- 双方共用一个共享场地区；任意玩家可在自己的主要阶段从手牌支付费用使用场地卡。
- 新场地进入时立即替换旧场地，旧场地进入其拥有者而非替换者的废弃区；替换不产生击溃或摧毁事件。
- 「罗德岛临时救护站」只在控制者自己的回合、受伤罗德岛干员主动撤退后触发，可治疗一名仍在部署区的受伤己方干员。
- 「整合运动临时营地」只在控制者自己的回合、己方整合运动干员被击溃后触发，可令候场区中另一张整合运动干员卡的 CD 减少1。
- 两张场地均按物理卡牌实体记录“每个己方回合限一次”；替换后的另一张同名实体拥有独立次数。
- 场地触发与干员触发进入同一确定性队列，重新检查合法目标，并允许玩家选择发动或跳过。
- 补齐碎骨部署时令敌方地面干员 DEF 降低2的触发效果，并统一按阵营校验“本回合撤退/击溃”前置条件。
- 覆盖测试会校验两套预组当前全部35个效果 ID 均已分配到关键词、触发、主动能力、战术支援或场地实现。
- 对局快照升级为 v10，保存当前共享场地、控制者及按来源对象记录的能力使用次数。
- 首测规则歧义与玩法观察记录在 `docs/module-6-playtest-notes.md`。

## 模块 7 拆分

- 7.1：双人房间与开局准备。创建/加入房间、邀请码、双方选择预组、准备状态与房主开局。
- 7.2：服务器权威对局状态。把本地规则内核接入房间，并只向客户端开放当前玩家可执行的指令。
- 7.3：断线恢复与私密信息。恢复席位与未完成操作，按玩家隔离手牌、牌库和秘密调度信息。
- 7.4：双端完整回归。覆盖交接逻辑替换、胜负结算、异常指令和整局对战验收。

## 模块 7.1 验收范围

- 新增“双人对战”入口，同时保留原有本地热座“对局原型”供规则回归。
- 玩家可输入名称、选择预组并创建房间，服务端生成六位邀请码。
- 第二台设备可通过邀请码加入；房间最多容纳两名玩家，并显示双方席位、在线状态、预组与准备状态。
- 每名玩家只能修改自己的预组和准备状态；准备后锁定预组，取消准备后可继续修改。
- 只有房主能在双方在线且准备完成后开始房间；开始后禁止继续修改。
- 房主离开时，剩余玩家自动成为玩家 1 与新房主，并取消原准备状态。
- 短暂网络断开会撤销房间就绪状态；Socket 重新连接后自动恢复当前席位。
- 房间服务对名称、邀请码、预组与会话身份进行服务端校验；核心房间状态与界面流程均有自动化测试。

模块 7.1 建立的房间与准备状态现已在模块 7.2 接入联网棋盘。

## 模块 7.2 验收范围

- 房主开始房间时，由服务端使用双方已锁定的预组创建唯一对局状态；玩家 1 固定先手，房间邀请码参与可复现随机种子。
- 浏览器不再直接修改联网对局状态，只向服务端发送经过结构校验的规则指令；服务端调用与本地热座相同的规则内核验证并执行。
- 会话身份与玩家席位绑定，服务端拒绝替另一名玩家进行调度、推进回合或执行卡牌操作的请求。
- 对局状态通过 Socket.IO 实时广播；部署、撤退、战术支援、场地、主动技能、攻击、防守和触发队列沿用模块 1 至 6 的完整实现。
- 原本用于单设备热座的回合、防守和触发交接由服务端自动完成，两台设备无需再点击“接手”。
- 每台设备固定以本人为下方视角展示台面和本人手牌；非当前行动玩家可以查看同步后的台面，但不能执行回合操作。
- 起手调度、战术支援分步结算、防守响应和触发选择只在应操作玩家的界面显示，对手显示等待同步状态。
- 短暂断线后会恢复房间席位并重新下发最新服务器对局状态；对手在线状态会显示在联网对局顶部。
- 房间状态机、联网自动交接、固定玩家视角和真实双 Socket 客户端流程均经过测试。

模块 7.2 的服务端状态仍保存在内存中，重启房间服务会清空对局。模块 7.3.1 已补齐按玩家裁剪的私密状态协议，后续 7.3.2 与 7.3.3 将继续处理刷新恢复和服务端持久化。

## 模块 7.3 拆分

- 7.3.1：玩家专属私密状态。隔离双方手牌、牌库顺序、检索牌与服务端随机种子。
- 7.3.2：浏览器断线恢复。持久保存房间身份，刷新页面后恢复原席位和对局。
- 7.3.3：服务端对局持久化。房间服务重启后恢复未结束对局，并清理过期房间。

## 模块 7.3.1 验收范围

- 服务端不再向整个房间广播同一份对局状态，而是按照玩家席位分别生成并发送专属视图。
- 玩家只能收到自己手牌中卡牌的真实实例与定义；对手手牌只保留数量，并使用不可解析的占位标识。
- 双方牌库都只下发剩余数量，不下发真实实例、卡牌定义或顺序；客户端不能通过自己的网络状态提前查看后续抽牌。
- 服务端使用不可从房间邀请码推导的随机种子，并在客户端视图中移除真实种子与随机数状态。
- 牌库检索和牌库底排序中的卡牌只对效果控制者公开，对手只知道正在进行该结算及涉及的牌数。
- 部署区、再部署候场区、废弃区、共享场地、持续效果来源和触发来源继续作为公开信息完整同步。
- 玩家发送指令后的确认响应同样使用本人专属视图，不会通过响应数据绕过广播隔离。
- 专属视图通过深拷贝生成，不会修改服务端保存的权威状态；隐私裁剪和公开区域保留均有自动化测试覆盖。

模块 7.3.1 不保存浏览器刷新后的会话身份，也不持久化服务器内存状态；这两部分依次由 7.3.2 和 7.3.3 完成。

## 模块 7.3.2 验收范围

- 创建或加入房间后，将玩家 ID、会话令牌和邀请码保存在当前标签页的 `sessionStorage` 中；刷新页面不会丢失身份。
- 会话按标签页隔离，同一浏览器可用两个普通标签分别测试玩家 1 与玩家 2，不会因共享 `localStorage` 覆盖身份。
- 页面重新载入后自动连接房间服务、恢复原席位，并重新接收本人专属的最新房间与对局状态。
- Socket 短暂断线并自动重连时，使用已有令牌重新绑定新连接，不需要重新输入邀请码或重新准备。
- 新连接恢复成功后，旧 Socket 立即失去房间修改和对局指令权限，避免同一席位被两个连接同时控制。
- 房间服务暂时不可用时保留会话并显示重试界面；玩家可重试恢复，或主动放弃保存的身份返回大厅。
- 房间已经关闭或令牌失效时自动清除无效会话，避免页面永久停留在恢复状态。
- 恢复后下发的对局状态继续经过 7.3.1 的玩家专属裁剪，不会因重连泄露对手私密区域。

模块 7.3.2 只能恢复仍存在于当前房间服务内存中的对局；房间服务进程重启后的恢复将在模块 7.3.3 接入。

## 模块 7.3.3 验收范围

- 房间、玩家席位、会话令牌、准备状态与完整服务端权威对局状态会保存至 `server/data/rooms.json`。
- 每次创建、加入、准备、恢复、开局、规则指令、离开或断线后更新快照，已确认的操作不会只停留在进程内存中。
- 快照先写入同目录临时文件，再通过原子重命名替换正式文件，避免写入中断留下半份 JSON。
- 房间服务启动时使用运行时 schema 校验快照；卡牌实例、触发队列、持续效果、随机状态及双方私密区域均按完整 `GameState` 恢复。
- 从磁盘恢复时所有旧 Socket 均标记为离线；浏览器随后使用 7.3.2 保存的令牌重新绑定，并接收 7.3.1 裁剪后的本人视图。
- 默认清理超过 24 小时未活动且当前无人在线的房间，同时删除关联会话；在线房间不会被定时清理。
- `ATCG_ROOM_STATE_PATH` 可覆盖快照位置，`ATCG_ROOM_MAX_AGE_MS` 可调整房间保留时间。
- `server/data/` 已加入忽略列表，不会把真实会话令牌和对局内容提交进代码仓库。
- 自动化测试覆盖房间与令牌恢复、完整权威状态恢复、旧连接离线化、原子文件替换及过期房间清理。

模块 7.3 至此完成。下一步模块 7.4 将进行双端完整对局、掉线与服务重启、非法指令和胜负结算的最终回归。

## 模块 7.4 拆分

- 7.4.1：联机指令可靠性。加入对局版本号，拒绝重复、过期与乱序指令。
- 7.4.2：对局生命周期。接入认输、对手退出、胜负展示和房间收尾。
- 7.4.3：双端完整回归。覆盖完整对局、断线、服务重启与异常路径。

## 模块 7.4.1 验收范围

- 每个服务端权威对局维护独立、单调递增的 revision，开局版本为 0。
- 服务端下发的玩家专属状态与指令确认响应统一使用 `{ revision, state }` 快照。
- 客户端提交规则指令时必须携带当前 `expectedRevision`；缺失、负数或非整数版本会被协议校验拒绝。
- 服务端在执行规则内核前检查版本，仅接受与当前 revision 完全匹配的指令。
- 指令成功后，对局状态与 revision 在同一同步处理过程中更新；重复发送同一旧版本指令不会再次生效。
- 客户端只接纳不低于当前 revision 的状态，迟到的旧广播或旧确认响应不能覆盖新棋盘。
- revision 随房间快照持久化并在服务重启后恢复；旧版 7.3.3 快照缺少该字段时自动迁移为 0。
- 自动化测试覆盖成功递增、重复提交拒绝、状态不被旧请求修改、旧快照兼容和客户端旧包过滤。

模块 7.4.1 完成后，下一步进入 7.4.2 的认输、离场与胜负生命周期。

## 模块 7.4.2 验收范围

- 规则内核产生的牌库抽空或理智盾归零会同步把房间切换为已结束状态，双方进入同一份权威结算。
- 联机界面始终提供认输入口，并要求二次确认；认输方判负，对手立即收到胜利结果。
- 对局中的普通断线只更新在线状态并保留席位，不会误判为失败；玩家仍可刷新或重连继续对局。
- 玩家主动离开尚未结束的对局时视为弃权，对手获胜；主动离开的玩家清除本标签页会话并返回大厅。
- 结算页按本人视角显示胜利、失败或平局，并区分牌库抽空、理智盾耗尽、认输和主动离场。
- 已结束房间保留双方席位与结果，允许断线玩家恢复查看；双方分别返回大厅后才删除房间和会话。
- 对局结果、房间结束状态与最新 revision 一同持久化；服务重启后仍可恢复结算页。
- 旧快照若已有结束的 `GameState`、但房间仍标记为进行中，会在加载时自动规范为已结束状态。
- 自动化测试覆盖认输结算、重复结算拒绝、二次确认、本人视角结果、结束房间释放及持久化恢复。

模块 7.4.2 完成后，模块 7 仅剩 7.4.3 的双端完整回归与最终玩法验收。

## 模块 7.4.3 验收范围

- 新增真实 Socket.IO 双客户端回归测试，而不是只调用房间状态类或规则内核。
- 回归流程覆盖创建与加入房间、双方准备、服务端开局和两名玩家秘密调度。
- 同一局中验证双方只能读取自己的真实手牌，对手手牌始终保持不可解析的占位数据。
- 验证合法指令令 revision 递增、重复旧指令被拒绝，且不会二次修改权威状态。
- 验证 Socket 断开后使用原令牌恢复席位、最新 revision 与本人专属私密视图。
- 在测试中真实停止并重启房间服务，随后恢复双方席位和未结束的权威对局。
- 恢复后继续完成认输结算，确认双方收到相反视角的同一结果，并在双方离开后释放房间身份。
- 联机棋盘显示当前同步 revision 和指令提交状态；客户端提交期间不会重复发送操作。
- `npm run test:e2e` 可单独执行真实双端链路；`npm run check` 会连同全部规则测试一并执行。
- 最终人工验收矩阵记录在 `docs/module-7-final-acceptance.md`。

模块 7.4.3 完成后，模块 7 的双人联网原型形成完整闭环。后续工作应转向实战试玩反馈、规则平衡与产品化部署，而不是继续扩展基础联网链路。

## 模块 8 拆分

- 8.1：生产运行基座。单端口托管前端与 Socket.IO，支持云平台端口、健康检查和优雅停机。
- 8.2：托管平台配置。加入 Render 部署声明、临时快照路径与环境变量模板。
- 8.3：公网验收与运维保护。验证真实公网双端、日志、限流、备份与故障恢复。

## 模块 8.1 验收范围

- `npm run build` 生成前端文件后，`npm start` 使用一个 Node 进程同时提供网页、Socket.IO 和 `/health`。
- 服务器优先读取 `ATCG_SERVER_PORT`，其次读取通用云平台环境变量 `PORT`，本地默认仍为 4174。
- `/` 和无扩展名的前端路由返回 `dist/index.html`；缺失的脚本、样式等静态资源保持 404，不错误回退到首页。
- 带内容哈希的 `dist/assets` 使用长期不可变缓存，入口 HTML 使用 `no-cache`。
- 静态响应包含内容类型保护、禁止嵌入、来源策略与 CSP；CSP 允许现有动态定位样式、同源媒体和 WebSocket。
- 静态文件解析限制在 `dist` 内，编码后的目录逃逸请求不会读取工程文件。
- 前后端默认使用同源通信，不开放任意来源 CORS；确需拆分域名时通过逗号分隔的 `ATCG_ALLOWED_ORIGINS` 显式放行。
- 收到 `SIGTERM` 或 `SIGINT` 后停止清理定时器、同步保存房间快照、关闭 Socket 与 HTTP 连接，并设置强制退出超时。
- 自动化测试覆盖首页、SPA 回退、资源缓存、安全头、缺失资源和目录逃逸；真实双 Socket 回归继续通过。

模块 8.1 只完成可部署的运行方式，尚未创建任何云端资源。模块 8.2 将加入具体托管平台配置。

## 模块 8.2 验收范围

- 根目录新增 `render.yaml`，以 Render Blueprint 声明单个 Node Web Service。
- Blueprint 使用 `npm ci --include=dev && npm run build && npm prune --omit=dev` 构建，并以 `npm start` 启动生产服务。
- 服务固定为一个实例，配置 `/health` 健康检查和 30 秒最大优雅停机时间。
- 当前采用 `free` 免费计算方案，不创建付费持久磁盘。
- `ATCG_ROOM_STATE_PATH=/tmp/rooms.json`，主备快照只用于实例当前生命周期内的故障保护。
- 免费实例休眠、重启或重新部署后可能丢失 `/tmp` 中的房间和对局，不用于验证跨实例恢复。
- `ATCG_ROOM_MAX_AGE_MS=86400000`，继续使用 24 小时未活动房间清理策略。
- `tsx` 调整为生产依赖，确保构建后执行 `npm prune --omit=dev` 仍可运行服务。
- Node 引擎约束为 `>=22.12.0 <25`，与当前 Vite 运行要求和已验证环境一致。
- 新增 `.env.example`，真实 `.env` 默认忽略；`server/data/` 继续不进入版本库。
- `npm run check:deploy` 校验 Blueprint 与项目生产脚本的一致性并执行生产构建。
- 完整部署步骤、免费方案限制和部署后检查记录在 `docs/module-8-render-deployment.md`。

模块 8.2 不会自动创建云端资源或产生费用。

## 模块 8.3 验收范围

- Socket.IO 单条消息限制为 128 KiB，避免异常大载荷占用服务内存。
- 创建、加入与恢复房间按来源地址限流；房间控制和对局指令按 Socket 分组限流，默认窗口为 60 秒。
- 限流参数可通过 `ATCG_ENTRY_RATE_LIMIT`、`ATCG_CONTROL_RATE_LIMIT` 与 `ATCG_COMMAND_RATE_LIMIT` 调整。
- 服务日志改为单行 JSON，记录启动、快照恢复、房间生命周期、限流和停机事件；令牌、随机种子、手牌及完整对局状态会被遮蔽。
- 每次覆盖主快照前，将上一代有效快照原子写入 `ATCG_ROOM_BACKUP_PATH`。
- 主快照缺失或损坏时自动从备份恢复并修复主文件；主备份都损坏时拒绝带着空状态静默启动。
- Render 免费实例在运行期保存 `/tmp/rooms.json` 与 `/tmp/rooms.backup.json`；实例重置后不保证保留。
- `npm run check:ops` 执行限流、日志、主备恢复与真实双 Socket 回归测试。
- 公网部署后的人工演练和日志查询方法记录在 `docs/module-8-public-operations.md`。

模块 8.3 完成代码侧公网保护，但不会自动创建 Render 服务、产生费用或操作云端账号；真实公网地址需要按部署指南由你确认创建。

## 干员牌面美术

- 已部署干员会按卡名自动查找 `src/art/<干员名>_Vertical.webm` 与 `src/art/<干员名>_Horizontal.webm`。
- 竖置状态使用 `Vertical`，横置、攻击与拦截后的状态使用 `Horizontal`。
- 动画作为牌面底图静音播放；竖置素材循环，横置素材在状态切换后只播放一次。位置、站位、名称、ATK、DEF、生命和操作按钮显示在美术覆盖层上。
- 当前目录中的素材会自动匹配；没有对应素材的干员继续使用原有牌面样式。
- 塔露拉横置时继续使用 `塔露拉_Vertical.webm`，避免横置素材末帧透明导致牌面人物消失。
- 后续按相同命名规则加入 WebM 文件即可自动生效，不需要修改资源映射代码。
- 预组浏览中的干员牌固定使用 220px 规则框；长效果显示摘要，点击牌面可在详情窗口查看完整文本，因此不同文本量不会改变卡牌尺寸。

## 命令

```powershell
npm install
npm run import:cards -- --rhodes "<罗德岛预组.xlsx>" --reunion "<整合运动预组.xlsx>"
npm run check
npm run test:e2e
npm run check:deploy
npm run check:ops
npm run dev
npm run build
npm start
```

`npm run dev` 会同时启动 Vite 页面（默认 4173）与房间服务（默认 4174）。同一局域网内的第二台设备可打开终端中 Vite 输出的 Network 地址加入房间；若系统防火墙询问，请允许该本地开发服务访问专用网络。

`npm start` 是生产入口，需要先执行 `npm run build`。生产模式下页面与 Socket.IO 使用同一个端口；可通过 `PORT` 或 `ATCG_SERVER_PORT` 指定端口，通过 `ATCG_ROOM_STATE_PATH` 与 `ATCG_ROOM_BACKUP_PATH` 指定房间主备快照位置。
