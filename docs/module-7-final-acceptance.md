# 模块 7 最终双端验收

## 自动回归

运行：

```powershell
npm run check
npm run test:e2e
```

真实双端测试会启动独立的临时房间服务和临时快照，不读取或覆盖 `server/data/rooms.json`。测试结束后会关闭进程并删除临时数据。

自动流程依次验证：

1. 玩家 A 创建房间，玩家 B 使用邀请码加入。
2. 双方选择预组、准备，由房主开始对局。
3. 两端收到 revision 0 的不同私密视图，只能读取自己的真实手牌。
4. 双方依次完成秘密调度，revision 增加至 2。
5. 重复提交 revision 0 的旧指令被拒绝，权威状态不发生第二次变化。
6. 玩家 B 断线后使用原令牌恢复席位、私密视图和 revision。
7. 房间服务真实停止并从磁盘快照重启，双方恢复至同一未结束对局。
8. 玩家 A 认输，双方在 revision 3 收到玩家 B 获胜的结算。
9. 双方退出结算页后房间和会话被释放，旧令牌无法再次恢复。

## 浏览器人工验收

使用两个浏览器标签页，或同一局域网内的两台设备：

1. 打开 `http://127.0.0.1:4173/`，进入“双人对战”。
2. 分别创建和加入房间，选择不同预组并准备。
3. 确认双方只能操作自己的秘密调度，页面顶部 revision 随每次成功操作增加。
4. 部署干员并推进至少两个回合，确认非行动方只能查看、不能操作。
5. 刷新任意一端，确认自动恢复原席位、手牌和棋盘。
6. 暂时关闭一端标签页，确认另一端仅显示“对手已断开”，不会立即判胜。
7. 重新打开原标签页并恢复，继续执行一次攻击、防守响应和触发能力结算。
8. 任意一方点击“认输”，第一次点击只出现确认操作；确认后双方显示对应胜负。
9. 双方点击“返回对战大厅”，确认可以创建或加入下一局。

## 当前原型边界

- 房间服务仍是单进程本地原型，没有账号、匹配队列、观战、聊天或跨服务器扩展。
- 快照保存在本机 JSON 文件，适合玩法测试，不应作为正式线上数据库方案。
- 默认不使用 TLS；局域网试玩应只在可信网络进行。
- 断线不会自动判负。需要超时判负时，应在后续产品化阶段加入可配置的断线计时器。
